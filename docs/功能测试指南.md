# FluxAgent 功能测试指南

建议按“自动化回归 → 启动服务 → HTTP 功能 → 真实模型与记忆”顺序验证。当前工程是后端，没有独立前端；可以用 Swagger、curl 或 CLI 操作。下列终端命令适用于 macOS / Linux，在项目根目录执行。

## 1. 先运行自动化测试

需要 JDK 21。仓库提供 Maven Wrapper，不要求单独安装 Maven。

```bash
./mvnw clean verify
```

依赖已缓存且不需要联网下载时可用 `./mvnw -o clean verify`。成功标志是 `BUILD SUCCESS`，当前共 42 项测试，失败、错误、跳过均为 0。Jar 输出为 `target/flux-agent-0.1.0.jar`，详细结果在 `target/surefire-reports/`。

| 想验证的内容 | 可单独执行的命令 |
| --- | --- |
| HTTP、上传、参数校验、OpenAPI | `./mvnw -Dtest=ApiIntegrationTest test` |
| 聊天流程、记忆、CLI | `./mvnw -Dtest=ChatServiceTest,MemoryManagerTest,ChatCliTest test` |
| 模型配置、DeepSeek 请求、Jev 协议与降级 | `./mvnw -Dtest=ModelConfigurationTest,DeepSeekGatewayIntegrationTest,JevIntentClientTest,IntentRecognizerTest test` |
| 工具缓存、超时、熔断、检索、监控 | `./mvnw -Dtest=ToolExecutorTest,CircuitBreakerTest,KnowledgeToolManagerTest,PerformanceMonitorTest test` |

自动化测试隔离本地 `.env`，模型和 Redis 使用替身或本地 HTTP 服务。因此不需要真实 Key、Redis 或 Docker，也不能据此判断真实模型质量和 Redis 服务连接成功。

## 2. 启动用于手工验收的服务

已有 `.env` 时直接使用它；没有时才执行：

```bash
test -f .env || cp .env.example .env
```

真实模型验收需要在 `.env` 配置 `DMX_API_KEY`。当前默认配置为 DMXAPI、主模型 `deepseek-v4.1-flash-1017` 和意图模型 `jev-latest`。Base URL 为 `https://www.dmxapi.cn`；主模型路径是 `/v1/chat/completions`，Jev 路径是 `/typesafe/v1/systemone`。从项目根目录启动会自动导入 `.env`。

先启动 Redis（需要已安装并运行 Docker）：

```bash
docker compose up -d redis
docker compose ps redis
```

等待 Redis 显示 healthy。已有 Redis 服务也可以，按其实际地址设置 `REDIS_HOST`、`REDIS_PORT`、`REDIS_PASSWORD`；仓库 Compose 映射到宿主机的端口是 **6380**。

启动应用，把手工测试知识库、记忆文件和评测基线放到独立目录；Redis 使用专门的测试用户和会话 ID：

```bash
REDIS_PORT=6380 \
ECHOMIND_DATA_DIR=data/manual-test \
KNOWLEDGE_STORE_PATH=data/manual-test/knowledge-store.json \
MEMORY_STORE_PATH=data/manual-test/memory-store.json \
EVAL_BASELINE_PATH=data/manual-test/eval-baseline.json \
java -jar target/flux-agent-0.1.0.jar
```

也可以将最后一行换为 `./mvnw spring-boot:run`。在另一个终端执行后续 curl 命令；结束时在服务终端按 Ctrl+C。

```bash
curl -sS http://localhost:8080/health
curl -sS http://localhost:8080/v3/api-docs
```

`/health` 应返回 `status: "ok"`。它只反映应用接口可响应，并不验证 Redis 或外部模型。需要时用 `/actuator/health` 查看包含 Redis 的依赖健康状态。

在浏览器打开 `http://localhost:8080/docs`，找到接口，点击 **Try it out → Execute**。标题和接口分组为 FluxAgent。页面依赖 jsDelivr CDN；页面空白时先检查 CDN 访问，或者直接使用 curl。

## 3. 聊天与 Agent 路由

```bash
curl -sS http://localhost:8080/chat \
  -H 'Content-Type: application/json' \
  -d '{"message":"你好","user_id":"manual-user","conv_id":"manual-greeting"}'
```

检查 `response` 非空、`conv_id` 等于请求值，并记录 `intent`、`agent_type`、`escalated`、`latency_ms`、`intent_confidence` 和 `intent_source_scores`。可将消息和会话 ID 替换为下列样本，每个独立场景用不同会话：

| 场景 | 示例消息 | 观察重点 |
| --- | --- | --- |
| 问候 | 你好 | 问候意图、general 路由 |
| 技术支持 | 登录一直返回 401，怎么排查？ | 技术意图、technical 路由 |
| 退款 | 我要申请订单 #FA1001 的退款 | 退款意图、billing 路由、订单实体 |
| 人工协助 | 我要投诉，请转人工客服 | 升级意图和 `escalated` |
| 知识问答 | 星河测试套餐退款需要几个工作日？ | 先导入下一节文档，再核对事实 |

模型输出、置信度和路由可能受历史消息、降级及监控反馈影响，不要求回答逐字相同。`escalated=true` 是系统建议转人工的标识，当前没有外部人工客服工单系统接入。

### 确认真实模型确实工作

- **主模型**：核对回复内容及应用日志。出现 `Spring AI chat failed, using deterministic fallback` 表示该次主模型调用走了本地兜底；部分退款/技术类兜底话术没有“模型不可用”字样，不能只看回复文字。
- **Jev**：高置信度分类被采用时，`intent_source_scores` 包含 `jev`。没有该字段说明当前使用了其他识别来源，需要检查 `JEV_ENABLED`、密钥、超时和日志。
- 严格验证主模型时，在上述启动命令前增加 `LLM_FALLBACK_ENABLED=false`。这会关闭网关的固定话术兜底；上层仍可能捕获异常或转人工，需同时检查日志及响应。
- **HTTP 200、`verified=true`、`grounded=true` 都不能单独证明真实模型成功调用**。这些是接口/应用字段。真实模型测试会使用配置的 API 额度。

## 4. 知识导入、检索与持久化

添加一条容易核对的测试知识：

```bash
curl -sS http://localhost:8080/knowledge/add \
  -H 'Content-Type: application/json' \
  -d '{"documents":[{"title":"星河测试套餐退款政策","content":"星河测试套餐在购买后七天内可申请退款，审核通过后两个工作日原路退回。"}]}'

curl -sS http://localhost:8080/knowledge/stats

curl -sS http://localhost:8080/search \
  --data-urlencode 'query=星河测试套餐退款' \
  --data-urlencode 'topK=3'
```

导入应返回 `added_chunks > 0`；检索应返回 `success=true`，`results` 包含刚导入的内容。`reranked=false` 表示没有完成模型重排，不能直接理解为检索失败。`success=false` 时检查 `error`。

接着通过 `/chat` 问“星河测试套餐退款需要几个工作日？”，观察 `knowledge_used` 并人工核对回答是否包含“审核通过后两个工作日”。该字段只说明检索上下文被使用，回答质量仍需核对。

上传文件可这样测试：

```bash
mkdir -p data/manual-test
printf '%s\n' '星河测试套餐客服时间为工作日 09:00 到 18:00。' > data/manual-test/faq.txt
curl -sS http://localhost:8080/knowledge/upload \
  -F 'file=@data/manual-test/faq.txt'
```

支持 `.txt`、`.md`、`.json`，文件上限 10MB；JSON 文件内容应是 `[{"title":"标题","content":"正文"}]` 数组。重启应用时保持相同存储路径，再检索该文档，可验证 JSON 持久化。重复导入会增加片段，验收后可保留这份独立测试数据。

当前主检索是本地 BM25 + hash vector，模型参与查询改写与重排；默认流程不依赖 ChromaDB，也没有使用专门的 Embedding 模型。

## 5. 多轮记忆

在 Redis 可用且真实模型工作时，连续请求必须使用同一组 `user_id` 与 `conv_id`：

```bash
curl -sS http://localhost:8080/chat \
  -H 'Content-Type: application/json' \
  -d '{"message":"我的订单号是 FA90210，请帮我记住。","user_id":"manual-memory-user","conv_id":"manual-memory"}'

curl -sS http://localhost:8080/chat \
  -H 'Content-Type: application/json' \
  -d '{"message":"我刚才说的订单号是什么？","user_id":"manual-memory-user","conv_id":"manual-memory"}'
```

预期第二轮能回答 `FA90210`。在 Redis 正常、消息未过期的前提下，重启应用后用同一 ID 再问，可以验证工作记忆保留。日志中出现 Redis 读取/写入失败时，即使聊天返回成功，也没有完成记忆验收。仅更换会话 ID 不能证明用户级画像/长期记忆隔离；独立测试应同时换用户 ID。

## 6. CLI、Skills 与监控

结束 HTTP 服务后，可以沿用第 2 节的存储环境变量，将最后一行替换为：

```bash
java -jar target/flux-agent-0.1.0.jar --cli --user-id=manual-cli
```

CLI 不监听 HTTP 端口。输入消息验证回复，`/help` 查看帮助，`/new` 新建会话，`/exit` 或 `/quit` 退出。需要续聊时增加 `--conversation-id=已有会话ID`。

HTTP 服务运行时还可检查：

```bash
curl -sS http://localhost:8080/skills
curl -sS -X POST http://localhost:8080/skills/reload
curl -sS http://localhost:8080/monitor
curl -sS http://localhost:8080/metrics
```

`/skills` 检查 Skill 加载数量和解析错误；reload 后应重新读取配置目录。发送聊天请求后检查 `/monitor` 的统计、`active_alerts`、`resolved_alerts`。指标保留 `echomind_chat_duration_seconds_bucket` 和 `echomind_tool_success_rate` 等兼容名称；短时间少量请求不一定触发告警。

## 7. 意图与对话质量评测

使用第 2 节的独立 `EVAL_BASELINE_PATH`。每次评测会读取已有基线作比较，然后覆盖该路径上的基线文件。

先用少量明确样本验证意图：

```bash
curl -sS http://localhost:8080/eval/run \
  -H 'Content-Type: application/json' \
  -d '{"intent_cases":[{"message":"你好","expected_intent":"greeting"},{"message":"我要退款","expected_intent":"refund"}],"dialog_cases":[]}'
```

再增加多轮对话及模型评分：

```bash
curl -sS http://localhost:8080/eval/run \
  -H 'Content-Type: application/json' \
  -d '{"intent_cases":[],"dialog_cases":[{"turns":["我登录时返回401","已经重置密码，仍然失败"],"user_id":"manual-eval","conversation_id":"manual-eval-dialog"}]}'
```

观察 `pass_rate`、`avg_scores`、`per_class`、`regressions` 及 `results`。对话结果的 `metadata.judge_failed` 应为 false；否则先排查评分模型失败。上面两份样本集用途不同，不应把其基线差异当作质量退化；正式比较时保持样本集和配置一致，或使用不同的基线路径。

`{}` 会使用内置默认用例并产生更多模型调用。默认用例中部分粗粒度标签与 Jev 的细粒度结果可能不同，正式评测应按照 `IntentCategory` 中的标签构建业务样本。目前对话评测直接调用 `AgentOrchestrator`，不覆盖 `ChatService` 完整的 Redis、RAG 与回答校验链；仍需完成前面的 `/chat` 验收。

## 8. 异常输入

```bash
curl -i http://localhost:8080/chat \
  -H 'Content-Type: application/json' -d '{"message":" "}'

curl -i http://localhost:8080/search \
  --data-urlencode 'query=退款' --data-urlencode 'topK=0'
```

上述请求应返回 HTTP 400。上传不支持的扩展名或空文件应返回 400；超过 10MB 的文件应返回 413。

## 命名兼容说明

Java 入口、控制器和配置类分别为 `FluxAgentApplication`、`FluxAgentController`、`FluxAgentProperties`，业务包和 Maven groupId 统一为 `com.fluxagent`。

配置仍用 `echomind.*` / `ECHOMIND_*`；已有 Redis 键、存储元数据、监控指标及 Compose 服务名继续兼容。因此部署命令、已有 `.env` 和数据无需因 Java 更名而迁移。
