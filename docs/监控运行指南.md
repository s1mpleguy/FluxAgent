# FluxAgent 监控运行指南

监控包括应用内 Micrometer 指标、Prometheus 采集/查询、Grafana 看板。运行 Java 应用不会自动启动后两个进程。

## 本地运行（IDE 或 java -jar）

适用于 macOS/Linux。先启动 FluxAgent，确认 `http://localhost:8080/metrics` 可访问。macOS 首次安装依赖：

```bash
brew install prometheus grafana
```

本机已安装 Prometheus；Grafana 官方包放在被 Git 忽略的 `data/monitoring/vendor/grafana/`，脚本也支持从该目录寻找程序。其他机器仍需安装依赖。

其他系统使用官方原生二进制并放入 PATH；`grafana` 需要配套的 `conf`、`public` 目录，必要时设置 `GRAFANA_HOME`。在仓库根目录执行：

```bash
python3 scripts/monitoring.py start
python3 scripts/monitoring.py status
python3 scripts/monitoring.py check
```

`start` 等待两个服务就绪；应用指标最多再等待一个 10 秒采集周期。`check` 同时检查服务、应用 target、预配置看板和通过 Grafana 数据源发起的实际查询。

| 页面 | 地址 |
| --- | --- |
| Prometheus 查询/图表 | http://localhost:9091/graph |
| Prometheus 采集目标 | http://localhost:9091/targets |
| Prometheus 告警规则 | http://localhost:9091/alerts |
| Grafana 看板 | http://localhost:3000/d/fluxagent-overview/fluxagent |
| 应用监控 JSON | http://localhost:8080/monitor |

新版 Prometheus 打开 `/graph` 后可能跳转到 `/query`，属于正常页面迁移。

本地 Grafana 允许匿名只读查看；需要管理时用户名为 `admin`，随机密码保存在 `data/monitoring/grafana-admin-password`（仅当前用户可读，不入库）。两个监控服务只监听本机回环地址。脚本不读取模型 `.env`，不调用模型。

若应用端口不同：

```bash
python3 scripts/monitoring.py start --app-target 127.0.0.1:8082
```

修改采集目标后先停止再启动；重复启动相同配置不会创建第二份进程。停止监控：

```bash
python3 scripts/monitoring.py stop
```

停止不删除历史数据，也不停止 Java、Redis 或系统中其他监控服务。机器重启后再次执行 `start`；本脚本不安装开机启动任务。

## 容器运行

已有 Docker 的环境可以直接使用仓库 Compose：

```bash
docker compose up -d --build
docker compose ps
docker compose logs --tail=80 prometheus grafana
```

Compose 自动挂载相同的看板与 provisioning，Grafana 通过 `http://prometheus:9090` 查询数据；Prometheus 通过 `echomind-java:8080` 采集应用。容器主机上访问的端口仍为 9091、3000。本地原生模式与 Compose 不能同时占用这两个端口。

Grafana 默认提供匿名只读看板。容器管理员初始密码由 `GRAFANA_ADMIN_PASSWORD` 指定；未设置时遵循本地开发默认 `admin`，管理员首次登录需要修改。生产环境应配置自己的身份认证和网络入口。

## 看板内容与指标含义

预配置看板 `config/grafana/dashboards/fluxagent.json` 提供 22 个面板，可以选择应用实例，默认每 10 秒刷新。

- 请求：累计聊天数、每秒速率、P95、平均耗时、成功/失败趋势。
- Agent：每个 Agent 的请求数、执行成功率、累计平均耗时。
- 工具：请求数、成功率、缓存命中率、累计平均耗时、熔断状态。
- 告警：当前活动告警与保留的恢复记录（每实例最多 100 条）。
- JVM：CPU、堆内存、线程、GC 暂停时间。

旧的 `echomind_*` 指标继续兼容；新增 `fluxagent_*` 指标由本次版本提供。IDE 中正在运行的旧应用需要重新启动，才会出现新增指标。

| 指标 | 类型/含义 |
| --- | --- |
| `echomind_chat_duration_seconds_*` | 聊天 Timer 的直方图、次数和耗时；成功代表流程正常返回 |
| `echomind_agent_success_rate` | 所有 Agent 中最低的执行成功率 |
| `echomind_tool_success_rate` | 按调用次数加权的工具执行成功率 |
| `fluxagent_agent_requests{agent=...}` | 当前注册项的累计请求快照（Gauge） |
| `fluxagent_agent_success_ratio{agent=...}` | 各 Agent 执行成功率 |
| `fluxagent_agent_latency_seconds{agent=...}` | 各 Agent 自启动以来的平均耗时，单位秒 |
| `fluxagent_tool_requests{tool=...}` | 各工具请求快照，包含缓存命中与熔断拒绝 |
| `fluxagent_tool_success_ratio{tool=...}` | 各工具执行成功率 |
| `fluxagent_tool_latency_seconds{tool=...}` | 各工具累计平均耗时，单位秒 |
| `fluxagent_tool_cache_hits{tool=...}` | 各工具累计缓存命中快照 |
| `fluxagent_tool_cache_hit_ratio{tool=...}` | 命中数 / 有效参数调用数，未调用时为 0 |
| `fluxagent_tool_circuit_state{tool=...}` | 0 正常，1 熔断，2 恢复探测；未知为 NaN |
| `fluxagent_alerts_active` | 当前应用内活动告警数量 |
| `fluxagent_alerts_resolved_retained` | 内存中保留的恢复记录数量，不是累计恢复计数 |

新增 Gauge 从现有统计中每 10 秒采集一次，不应作为逐请求事件计数器使用；工具重新注册后统计归零，注销后指标移除。标签仅使用 Agent/工具注册名称。

未调用的 Agent/工具不展示成功率、平均耗时和命中率；原始统计仍保留默认值，查询通过请求数过滤。跨实例工具成功率卡片展示所选实例中最低的加权成功率。没有请求时，P95、平均耗时可能显示“暂无数据”；刚启动时 rate 也需要至少两个样本。不会用假数据填充空图。上述执行成功率不表示回答正确率；Accuracy、Macro-F1、Judge 分数尚未接入本看板。

Prometheus 示例查询：

```promql
up{service="fluxagent"}
sum(rate(echomind_chat_duration_seconds_count{service="fluxagent"}[5m]))
histogram_quantile(0.95, sum by (le) (rate(echomind_chat_duration_seconds_bucket{service="fluxagent"}[5m])))
fluxagent_tool_circuit_state{service="fluxagent"}
```

## 告警与故障定位

`config/prometheus-alerts.yml` 包含应用采集失败、聊天处理失败率、聊天 P95 和工具持续熔断规则。规则在 Prometheus `/alerts` 查看；没有配置 Alertmanager，因此 Prometheus 规则本身不会发送通知。现有应用内 `ALERT_WEBHOOK_URL` 告警仍独立工作。

| 现象 | 检查方法 |
| --- | --- |
| 9091 连接被拒绝 | 执行 `status`；检查是否安装并启动 Prometheus |
| 页面可开但应用 target 为 down | 本地 target 应为 `127.0.0.1:8080`，容器 target 为 `echomind-java:8080`；检查 `/metrics` |
| 3000 端口占用 | 检查原有 Grafana；脚本不会自动终止其他服务 |
| Grafana 没有看板 | 查看 `data/monitoring/grafana.log` 中 provisioning 错误 |
| 新指标暂无数据 | 重新启动新构建的 Java 应用，等待采集；检查 `/metrics` 是否有 `fluxagent_` |
| 状态文件与进程身份不符 | 检查记录的 PID 和实际进程；确认旧进程已退出后才移走状态文件 |
| 修改看板 JSON 后不更新 | 等待 provisioning 的 10 秒刷新，重新打开看板；不要在 UI 修改受配置管理的看板 |

日志、状态、随机密码和数据库都在被 Git 忽略的 `data/monitoring/`。启动失败先看对应 `.log` 文件。
