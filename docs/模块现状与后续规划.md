# 模块现状与后续规划

基于 2026-11-09 的代码和本次监控补全。以下区分可用能力、已完成的监控交付和仍未实现的扩展，避免把计划当作现有功能。

| 模块 | 当前状态 | 后续工作 |
| --- | --- | --- |
| HTTP / CLI 对话 | 已实现，共用 ChatService | 面向用户的聊天界面、流式响应 |
| 意图与多 Agent | 已实现 Jev、回退、主辅路由 | 专项路由准确率、并发与单 Agent 故障测试集 |
| Hybrid RAG | 已实现切片、BM25/hash、改写和重排 | 标注检索集、Recall@K/MRR、引用追溯；Chroma 主召回需先确定 Embedding 模型 |
| 工作/长期记忆 | 已实现 Redis、JSON 摘要和画像 | 真实 Redis 的跨重启、隔离、摘要保真评测 |
| Skills | 已实现加载与主动 reload | 完整的规则遵守率评测；没有文件自动监听 |
| 工具执行 | 已实现 TTL、超时、熔断、回退 | 本次补充缓存命中统计与细分指标；远程 MCP 协议尚未实现 |
| 运行监控 | 本次补齐启动管理、Grafana、细分指标和 Prometheus 规则 | 生产身份认证、集中告警投递按部署环境接入 |
| 质量评测 | 自写 Accuracy/Macro-F1/Judge/baseline | 完整 /chat 评测、固定基线与历史报告、评测看板 |

## 推荐的下一轮业务补全

1. 评测闭环：固定业务标注集，增加完整 ChatService 链路的评测入口，分开统计检索、路由和回答质量。baseline 当前每次运行都会覆盖，应引入独立报告与显式基线晋升。
2. 回答验证状态：当前 AnswerVerifier 异常时回退为 pass=true，应区分通过、失败和未完成校验；Judge 缺失字段默认 0.5 也需要明确标识。
3. 客服工作台：聊天、知识库导入、Skills 管理、评测报告浏览；当前 Grafana 只提供运行监控。

这三项需要相应的接口、数据与测试调整，不属于本次已完成能力。当前监控分数不作为回答正确性或生产验收的替代。
